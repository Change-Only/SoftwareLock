# 软件锁（Software Lock）

给 Windows 上的任意软件加一把锁。

- **打开软件锁本身** → 每次都要输入主密码（包括从托盘重新打开）
- **从软件锁界面里点「启动」** → 不需要密码，直接打开
- **在其他任何地方启动**（双击桌面图标 / 开始菜单 / 任务栏 / 命令行）→ 都必须先输入密码
- 没通过密码验证 → 进程被立即结束，程序打不开
- **退出软件锁需要密码**，且退出后**后台守护继续保护**——受保护的应用依旧打不开
- 软件锁默认以**管理员身份**启动，因此连管理员程序也能拦截
- 软件锁自己常驻托盘后台守护；在任务管理器里结束它会被自动拉起（互为守护）

---

## 一、直接使用

双击 `dist/软件锁.exe` 即可，无需安装、无需 Python 环境。

1. **首次运行**：弹出初始化窗口，设置主密码（至少 6 位），建议保持「开机自动启动」勾选。
2. **添加要加锁的软件**：点「添加应用」，选择目标程序的 `.exe`。
   - 如果该程序当前正在运行，会被立即结束，保证加锁马上生效。
3. 完成。此后它在软件锁之外被启动时，就会弹出密码框。

界面底部可以随时看到「已保护 N 个应用 / 已拦截 M 次」。

### 托盘菜单

右键任务栏托盘里的小锁图标：

| 菜单项 | 说明 |
| --- | --- |
| 打开主界面 | 先验证主密码，通过后重新显示窗口（并恢复托盘图标） |
| 一键关闭全部受保护应用 | 按 exe 路径全量枚举并结束所有正在运行的受保护程序，同时清空解锁状态 |
| 退出软件锁 | **需要密码**。只退出可见界面：窗口与托盘图标消失，但后台守护继续运行，受保护应用仍然需要密码才能打开。再次双击 `软件锁.exe` 即可重新打开界面 |

说明：

- 「退出软件锁」会先弹出密码框；**取消或密码错误则什么都不发生**，软件锁保持运行。
- 「退出界面」之后，受保护的应用**依旧不能直接打开**——后台守护仍在拦截。
- 界面上**刻意没有**「彻底停止保护」的入口（避免被随手关掉）。若确需升级/卸载，
  用维护通道：`软件锁.exe --quit`（同样需要主密码）。
- 主界面里未提权时会出现橙色提示条，其中的「以管理员身份重启」同样需要密码。

### 关闭窗口

点窗口右上角的 ✕ 会直接隐藏到托盘（后台守护继续），没有任何弹窗、不需要密码。

## 二、工作原理

程序启动后有一个守护线程，用很短间隔（默认 120 毫秒，可在设置里调到 60 毫秒）做**增量进程扫描**——
只解析新出现的进程，开销极小。

一旦发现某个受保护程序的 `.exe` 被创建：

1. **立即挂起**该进程（冻结在启动瞬间，让它来不及画出界面）
2. **隐藏**它已经创建的窗口
3. 弹出密码验证框
4. 密码正确 → 恢复窗口、继续运行；密码错误 / 取消 / 超时 → **结束整棵进程树**

### 「放行」机制（什么时候不再要密码）

同一个程序通过密码放行后，在**它自己的进程还活着**的这段时间里，不会再重复索要密码。
这是必要的：微信、QQ、Chrome 这类程序在运行期间会反复启动自己的子进程，
如果每次都弹窗就没法用了。

**一旦这些进程全部退出，放行状态立即失效**（最长只多等一个扫描周期，约 120 毫秒），
所以「关闭程序 → 再打开」一定会重新要求输入密码。

此外，放行会话还要求**至少有一个放行进程持有可见窗口**：如果会话里的进程虽然活着、
却长时间（约 15 秒，给刚放行的应用留出初始化时间）连一个可见窗口都没有，
放行状态同样失效。这针对的是「本地服务 + 浏览器界面」型应用，以及关闭窗口后
在后台残留进程的应用——用户视角里应用早就关了，进程不该给会话无限续命。

放行状态是按**进程**记账的，只有两个来源可以免密：

| 免密来源 | 说明 |
| --- | --- |
| 在软件锁界面里点「启动」 | 界面刚发起的这次启动，其进程会被直接放行 |
| 应用自身的派生进程 | 父进程是本次已放行进程（含它退出后立刻接续启动的同名进程，例如 launcher 交接） |

其余任何来源——在资源管理器/桌面双击、从命令行运行、从别的程序里唤起——
父进程都不是上述两种，**一律需要输入密码**。

### 密码是怎么存的

不保存明文。使用 `PBKDF2-HMAC-SHA256`，20 万次迭代 + 16 字节随机盐，
校验用常数时间比较。

### 数据放在哪

数据目录默认与 `软件锁.exe` **同级**（便携模式），包含：

```
软件锁所在目录/
├─ 软件锁.exe
├─ config.json          配置（密码哈希、受保护列表、设置、统计）
└─ logs/app.log         运行日志
```

- 如果 exe 所在目录**不可写**（例如放在 `Program Files` 下），自动回退到
  `%APPDATA%\SoftwareLock\`。
- **从旧版本升级无需重新配置**：首次运行会自动把旧数据目录
  `%APPDATA%\SoftwareLock\config.json` 迁移过来，主密码和已保护的应用列表都会保留。

连续输错密码会进入冷却（默认 5 次后锁定 30 秒，可在设置里调整）。

## 三、设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 开机自动启动 | 关（初始化时勾选则为开） | 打包版优先用**计划任务**（最高权限，登录时不弹 UAC），失败回退到注册表启动项 |
| 以管理员身份运行 | 开 | 启动时自动提权，拦截管理员程序所必需；修改后需重启生效 |
| 防止被强制结束 | 开 | 双进程互为守护：在任务管理器里结束主进程，看守进程立即拉起；结束看守进程，主进程也立即补上 |
| 启动时清理已运行的受保护应用 | 开 | 软件锁启动时直接结束已在运行的受保护程序，防止绕过 |
| 后台扫描间隔 | 标准 120 毫秒 | 快速 60 毫秒拦截更及时，省电 300 毫秒更省 CPU |
| 连续输错锁定 | 5 次 / 冷却 30 秒 | 防暴力破解 |
| 杀毒软件误报 | — | 点「加入白名单」把软件锁的 exe 与数据目录写入 Windows Defender 排除项，避免被自动清理 |

## 四、已知限制

1. **软件锁默认以管理员身份启动。**
   启动时会请求一次 UAC 提权，这样才能拦截同样以管理员身份运行的程序
   （例如以管理员启动的终端、任务管理器）。若在 UAC 弹窗中点了「否」，
   软件锁会回退为普通权限运行，此时管理员程序无法被拦截——主界面顶部会出现
   橙色提示条，可点其中的「以管理员身份重启」（需密码）再次提权。

2. **检测有一个很短的时间窗。**
   默认扫描间隔下，程序可能有一瞬间（约 0.1 秒）的启动动作，
   随即被冻结并隐藏。把扫描间隔调成「快速（60 毫秒）」可以进一步缩小这个窗口。

3. **UWP / Microsoft Store 应用不适用。**
   这类应用不是普通的 `.exe`，加锁请选择传统的桌面程序。

4. **忘记密码无法通过界面找回。**
   密码是单向哈希存储的。如果真的忘了，需要手动删除数据目录里的
   `config.json` 重置（默认在 `软件锁.exe` 同级目录，同时也清空所有已加锁的程序列表）。

5. **只匹配完整路径。**
   加锁记录的是 `.exe` 的绝对路径。把同一个程序复制到别处再运行不会被拦截，
   库列表里也没有这个文件。

6. **界面上没有「彻底停止保护」的入口。**
   这是有意的：退出 = 后台继续保护，防止被随手关掉。确需停止（升级 / 卸载）时，
   执行 `软件锁.exe --quit` 并输入主密码。

## 五、被杀毒软件拦截怎么办

软件锁要做的动作（**以管理员身份运行、挂起其他进程、结束进程树、开机自启**）
和恶意程序的典型行为有重叠，因此**未签名的自编译程序很容易被杀软误报**，
表现为：文件刚放上去就被删掉、双击后被"已阻止"、运行几秒后进程消失。

按下面的顺序处理，通常第 1 步就够了：

1. **加入白名单（最有效，推荐）**
   打开软件锁 →「设置」→「杀毒软件误报」→ 点「**加入白名单**」。
   软件锁本身以管理员身份运行，会把自己的 exe 与数据目录加入 Windows Defender
   排除项，之后实时防护不会再检查它。

   如果提示失败（多半是系统开启了「篡改防护」），手动添加：
   `Windows 安全中心 → 病毒和威胁防护 → 病毒和威胁防护设置 → 管理设置 →
   排除项 → 添加或删除排除项 → 添加排除项 → 文件夹`，选中软件锁所在目录即可。

2. **换用便携目录版**
   `dist/软件锁便携版/软件锁.exe`。单文件版每次启动都要把自己解压到
   `%TEMP%\_MEIxxxx` 再运行，这个"自解压 + 临时目录执行"的行为是误报的高发特征；
   目录版不这么做，被拦的概率明显更低。整目录一起拷走即可使用。

3. **向微软提交误报**（想要根治的话）
   访问 <https://www.microsoft.com/wdsi/filesubmission> 选择
   "Submit a file for malware analysis"，上传 `软件锁.exe` 并在备注里说明
   这是自己编写的本地应用锁工具、无网络行为、源码可查。微软通常几天内更新特征库。

4. **根本解决：给 exe 做代码签名**
   有代码签名证书（EV 证书效果最好）后，用 `signtool sign` 签名，
   杀软与 SmartScreen 都会直接放行，不再需要排除项。

> 另外注意：如果 exe 是从聊天工具 / 网盘 / 邮件里拿到的，Windows 会打上
>"来自 Internet" 标记（Mark of the Web），此时双击还可能额外出现
>「Windows 已保护你的电脑」提示。右键文件 →「属性」→ 勾选「解除锁定」即可消除。

## 六、从源码运行 / 自己打包

### 环境

- Windows 10 / 11
- Python 3.9+（需要带 tkinter 的版本）

### 安装依赖

```bash
pip install -r requirements.txt
```

### 直接以源码运行

```bash
python src/main.py            # 正常启动
python src/main.py --minimized  # 直接最小化到托盘
```

### 自动化自检

```bash
python tools/selftest_interceptor.py    # 拦截引擎（不依赖界面）
python tools/selftest_unlock_scope.py   # 放行范围（关闭后重开必须重新要密码）
python tools/selftest_ui.py             # 界面构建 / 退出鉴权 / 搜索过滤 / 布局
python tools/smoketest_exe.py           # 打包产物端到端冒烟
```

`selftest_interceptor.py` 会用系统里 `cmd.exe` 的副本作为测试目标，验证：密码哈希、检测延迟、
拒绝时结束进程、放行时进程存活、运行期间多开免密、**关闭后立即重开必须重新输密码**、
立即锁定，以及窗口隐藏/恢复。

`selftest_unlock_scope.py` 专门盯住「放行什么时候失效」：进程退出后注销延迟、关闭后 0.2 秒 /
1.5 秒重开必须验证、会话内多开免密、界面启动免密、应用自身交接免密、pid 被复用不得误放行、
**无窗口僵尸进程不得给会话续命**、有窗口的正常会话不受无窗口规则影响。

`selftest_ui.py` 会真实构建主窗口与所有对话框，验证退出需密码、退出后后台仍保护、
搜索过滤、对话框不裁切等。测试数据全部落在临时目录，不影响真实配置。

> `smoketest_exe.py` 通过 `SOFTLOCK_DATA_DIR` 环境变量把被测 exe 的数据目录隔离到临时目录，
> 绝不写 `dist/config.json` —— 否则用户升级新版时会被判定为「已有配置」而跳过旧数据迁移。

### 打包

```bash
python build.py               # 同时产出「单文件版」和「便携目录版」
python build.py --no-portable # 只出单文件版
```

产物：

| 路径 | 说明 |
| --- | --- |
| `dist/软件锁.exe` | 单文件版，约 19 MB，双击即用、便于携带 |
| `dist/软件锁便携版/软件锁.exe` | 目录版（约 19 MB + `_internal/`）。**被杀软误报时优先用这个**，见第五章 |

打包时始终显式带 `--noupx`：UPX 压缩壳是杀毒软件误报的高发特征，故禁用。

> 重新打包时，上一版本的产物会先被改名成带时间戳的备份
> （`软件锁.exe.20260924-160000.bak` 这种形式），不会删除任何文件；
> 确认新版本可用后可以手动清理这些 `.bak`。

### 命令行参数

| 参数 | 用途 |
| --- | --- |
| `--minimized` | 启动后直接隐藏到托盘（开机自启用） |
| `--force-new` | 忽略单实例限制，强制启动一个新实例 |
| `--no-guard` | 不启动看守进程（调试用） |
| `--watchdog PID` | 内部使用，看守模式 |
| `--no-elevate` | 跳过管理员提权，直接以普通权限启动（调试 / 自动化测试用） |
| `--elevated` | 内部标记：本进程已由提权启动（提权后的新实例会带重试地等待单实例互斥体） |
| `--quit`（`--stop`） | 维护通道：完全停止软件锁并停止保护（需输入主密码），供升级 / 卸载使用 |
